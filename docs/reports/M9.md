# M9 release validation

The release candidate adds a standalone Node production server, clean-commit packaging and exact corresponding source access. The server validates its release manifest before listening, serves compressed assets with strict security and privacy headers, bounds lookup requests and quotas, and supports direct TLS or an explicitly trusted HTTPS proxy. Manual coordinates and zone entry remain available when lookup is disabled or unavailable. See [deployment.md](../deployment.md).

The content catalogue includes specific Wikipedia navigation links while preserving claim-level attribution and canonical word budgets. The independent numerical audit compares freshly calculated Swiss results with 80 retained JPL Horizons fixtures; all meet the fixed 60-arcsecond tolerance. Native integration and construction residual evidence remain in the earlier milestone reports. See [Horizons validation](horizons-validation.md) and [content/source/licence audit](content-source-licence-audit.md).

Final plan review found unrestricted camera panning and incomplete interrupted-gesture cleanup. Both are corrected. Blur, capture loss and real context restoration preserve the current exterior or observer pose, discard residual damping and permit the next drag. Four browser regressions exercise the actual uploaded camera matrices. Browser and worker schemas explicitly disable Zod's evaluation-based optimization so the production policy can permit WebAssembly compilation without JavaScript evaluation.

## Packaged latency and transfer

Measurements used the identified RTX 3060 desktop, Chromium 156.0.8078.4, 1920×1080 at DPR 1. Other owned browser and heavy verification jobs were held during this measurement window. Both reports identify the actual served commit, tree, source archive and manifest hashes.

| Measurement | Result | Scope |
| --- | ---: | --- |
| Selection feedback |18.7 ms p95, 36.6 ms maximum|30 alternating Sun/Moon selections|
| Warm chart update |27.6 ms p95, 32.9 ms maximum|30 successive one-hour updates; bodies, primary houses, aspects and UI|
| Normal one-day Moon trail |2.7 ms feedback, 80.9 ms first usable path|Warm scene/assets after the 30 steps, separate trail worker, five sampled points|
| Cold first usable scene |2.036 / 1.870 / 1.832 seconds|Three fresh contexts, aggregate 20 Mbps + 40 ms response delay|
| Cold encoded payload |2,309,279 bytes each run|Actual served body bytes, including 552,625 JS/CSS bytes, 163,634 WASM bytes and 1,592,451 ephemeris bytes|

Raw samples and transfer phases are retained in [M9-ui-latency.json](M9-ui-latency.json) and [M9-cold-load.json](M9-cold-load.json). Cold transfer uses a raw HTTP proxy that preserves Brotli bytes and shares one pacing clock across page and worker responses. This is a documented application-layer network profile, not a real last-mile link or physical scanout measurement. Three-run p95 equals the maximum and does not establish a population percentile. Browser-process/driver caches outside the fresh contexts can remain warm. There were no page errors or blocked requests in these runs. See [the method](../cold-load-measurement.md).

The initial Ubuntu CI run exposed Firefox's disabled headless WebGL2 environment. The test-only Linux profile uses headed Firefox under Xvfb with Mesa llvmpipe and a fail-fast GLSL draw/readback preflight; it does not skip rendering tests or change deployed browser settings. See [Linux browser CI](../linux-browser-ci.md). The actual backend proof and full remote suite are merge requirements, with their exact run/head recorded in [PR #12](https://github.com/buttery-x3/astrology-viewer/pull/12). Final source checks pass 515 tests across 37 files, plus type and lint checks.

## Acceptance boundary

This is an engineering release candidate, not completed external acceptance. The [requirement audit](../RELEASE_ACCEPTANCE.md) and [manual validation protocol](../manual-validation.md) leave five explicit gates open: actual Safari on macOS, an actual desktop screen reader, the reference integrated-GPU laptop, moderated participants and a human editor's claim-to-passage review. Agent/engineering review does not establish that any of these occurred. The final development-to-main PR must preserve this distinction and leave main unchanged.
