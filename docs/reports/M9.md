# M9 release validation

The release candidate adds a standalone Node production server, clean-commit packaging and exact corresponding source access. The server validates its release manifest before listening, serves compressed assets with strict security and privacy headers, bounds lookup requests and quotas, and supports direct TLS or an explicitly trusted HTTPS proxy. Manual coordinates and zone entry remain available when lookup is disabled or unavailable. See [deployment.md](../deployment.md).

The content catalogue includes specific Wikipedia navigation links while preserving claim-level attribution and canonical word budgets. The independent numerical audit compares freshly calculated Swiss results with 80 retained JPL Horizons fixtures; all meet the fixed 60-arcsecond tolerance. Native integration and construction residual evidence remain in the earlier milestone reports. See [Horizons validation](horizons-validation.md) and [content/source/licence audit](content-source-licence-audit.md).

Final plan review found unrestricted camera panning and incomplete interrupted-gesture cleanup. Both are corrected. Blur, capture loss and real context restoration preserve the current exterior or observer pose, discard residual damping and permit the next drag. Four browser regressions exercise the actual uploaded camera matrices. Browser and worker schemas explicitly disable Zod's evaluation-based optimization so the production policy can permit WebAssembly compilation without JavaScript evaluation.

## Evidence at the core implementation commit

- 514 unit, numerical, service and packaging tests pass across 36 files. The server/proxy tests require permission to open local sockets and create a temporary link on Windows.
- Type/Svelte checking, lint, content coverage, notice verification, asset checksums and whitespace checks pass.
- 305 engineering-curated entries, 240 placement combinations, 89 attributed sources and 91 canonical page budgets are retained. The production notice inventory has 53 records: 50 full upstream notice files and three explicitly recorded shorthand/banner cases.
- Physical RTX 3060 desktop scene measurements, stable resource counts, actual context recovery and source hashes are recorded in [M9-scene-performance.md](M9-scene-performance.md). Normal orbit meets a 16.7 ms callback p95 on that host; dense trails and mixed overlay stress have slower cadence and are reported separately.
- The Melbourne identity/date follow-up was separately reviewed and merged through [PR #11](https://github.com/buttery-x3/astrology-viewer/pull/11). At 1987-04-27 02:00 local, the Sun is Taurus 5.89° and the corresponding UTC instant is 1987-04-26 16:00. See [its report](sun-identity-follow-up.md).

Packaged standalone installation, complete three-engine browser workflows, the 63-view matrix, actual installed browser channels and cold/UI latency measurements are the next validation stage. Their final results must identify the tested artifact revision and retained evidence; preflight source runs are not substituted for packaged results.

## Acceptance boundary

This is an engineering release candidate, not completed external acceptance. The [requirement audit](../RELEASE_ACCEPTANCE.md) and [manual validation protocol](../manual-validation.md) leave five explicit gates open: actual Safari on macOS, an actual desktop screen reader, the reference integrated-GPU laptop, moderated participants and a human editor's claim-to-passage review. Agent/engineering review does not establish that any of these occurred. The final development-to-main PR must preserve this distinction and leave main unchanged.
