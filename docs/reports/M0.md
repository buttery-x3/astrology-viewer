# M0 feasibility result

25 October 2026. The owned, reproducible Swiss Ephemeris binding is feasible in the target browser-worker architecture.

## Verified

- Swiss Ephemeris `v2.10.3bfinal`, revision `f4dcd18e8005dde95fd8a8d2312ed12f9accd1b0`, compiled using Emscripten 4.0.23. The unmodified required upstream source and notices are included in `vendor/swisseph`.
- Both planetary/Moon files are hosted locally, SHA-256 verified before loading, and cover the product's 1900–2100 range. Extra model files, missing data, corrupt bytes, and non-Swiss fallback results are rejected.
- All ten body positions agree with pinned native output at four dates across the range. All seven systems agree at Greenwich and Sydney; polar Placidus/Koch results discard substitute cusps and retain valid celestial positions.
- True equatorial-of-date directions transformed by the engine rotation agree with separately requested J2000 directions. Geographic/horizon axes and handedness are covered by fixtures.
- UTC-labelled input, TT, and UT1 remain distinct. The wrapper explicitly reports historical UT1, modern UTC/leap-table, or future UT1-assumption branches. The tidal acceleration is explicitly fixed to DE431's −25.8, including in native reference commands, preventing call-order-dependent changes.
- Civil-time fixtures cover folds, gaps, non-hour transitions, a skipped day, historic seconds, century leap rules, manual offsets, and converted range bounds. Pre-1970 data limitations remain visible provenance, not a claim of complete historic coverage.
- Browser module-worker execution, local data loading, calculation, and polar failure states were exercised in actual Chromium.

## Review fixes

An independent subagent review identified and the implementation fixed:

1. Future time-model inference from rounded Julian dates: replaced with an explicit C-side branch result based on the pinned upstream leap table.
2. Inconsistent Delta-T policy between conversion and reported provenance: aligned and locked the model, and aligned native fixtures explicitly.
3. Unverified extra calculation files could override the model: additional files are now rejected.
4. A geographic vector comment incorrectly called the of-date frame inertial: corrected before scene integration.

The automated suite contains 37 passing tests, including regressions for the numerical/provenance findings. TypeScript and asset-manifest checks pass. Native fixture generation retains binary checksum, upstream provenance, input arguments, and data hashes.

## Reproduction

```text
npm ci
npm test
npm run check
npm run m0
node scripts/verify-assets.mjs
node scripts/install-browsers.mjs chromium
npm exec vite -- --host 127.0.0.1 --port 5194 --strictPort
```

In another shell set `PROBE_URL=http://127.0.0.1:5194` and run `node scripts/m0-browser.mjs`. Browser tests use the project-local `.cache/playwright` directory. Compiler rebuild instructions are in [m0-build.md](../m0-build.md).

## Architecture decision

Continue with the owned binding and direct Three.js architecture. The audited third-party wrapper was removed after finding insufficient time API coverage. Keep full pinned Moment data behind the time adapter, comprehensive geographic lookup server-side, and explicit historical uncertainty/manual correction. No numeric or performance acceptance criterion was waived to pass M0.
