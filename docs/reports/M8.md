# M8 — Accessibility, display quality and recovery

Implemented on `codex/m8-accessibility-recovery`, based on reviewed M7 development. Main remains unchanged.

## Delivered

- Compact native disclosure groups keep bodies directly available. Desktop panels collapse and restore keyboard focus; the inspector can stay pinned while its selection is cleared. A persistent demonstration badge prevents the example being mistaken for the user's birth chart.
- Larger rem-based typography, a large-text setting, improved contrast, underlined prose links and contextual legend disclosures improve readability and reflow. Selection announcements and quiet playback status avoid announcing every calculated frame. Keyboard controls include native group navigation, scene controls, search, exact timeline steps and Shift+arrow for ten configured steps.
- Auto/Low/High rendering, adjustable scene labels, translucent Earth and a resolved system/user motion preference preserve chart meaning. Low removes decorative grid/glow before semantic cores. Visible orientation, labelled zoom/focus/return actions and a nearby-feature chooser support equivalent mouse/keyboard inspection. Label placement moves labels with actual leaders while leaving astronomical markers fixed.
- Only a strict, versioned display-preference whitelist is persisted. Birth context, exploration instant/location and selections stay in session memory. Invalid or unavailable storage falls back to usable defaults.
- Finite streamed byte limits and whole-request deadlines cover assets and lookup, including a stalled body or non-cooperating request. Generation/revision/channel-safe worker watchdogs retain the last valid chart, explain failure and replace the worker on Retry. Cancellation and disposal clear timers/listeners. Lookup transmits only bounded place queries or coordinates; it omits credentials/referrers and avoids cache retention of those queries. See [recovery and privacy](../recovery-privacy.md).
- Independent review found and corrected a pending geographic lookup overwriting a manually confirmed IANA zone, and focus loss when compact drawers closed after selection or Escape. Late-success/late-error and narrow keyboard workflows now have regressions. Drawer layout and focus use the same 1000-pixel breakpoint, avoiding an unused inspector column at intermediate widths.

## Reported Melbourne Sun placement

The reported case is 27 April 1987 at 02:00, Australia/Melbourne, latitude −37.814°, longitude 144.96332°. Both the working build and the user's development server on port 8867 resolved it to **26 April 1987, 16:00 UTC**. Native Swiss and the current WASM engine agree on Sun longitude **35.891992831°**, or **Taurus 5.89°**. Repeated December–April changes restored the same geometry. The reported Sagittarius result was not reproduced, so this evidence does not establish the cause of every observed occurrence.

One visual defect was reproduced: exterior-hemisphere culling could hide the selected body's linked Taurus glyph despite its visible marker and highlighted belt. Linked sign labels now receive selection priority while respecting actual Earth occlusion. Body hover identities show the tropical sign, degree and below-horizon state, and refresh against new geometry even with a stationary pointer. A production-browser regression observes the Taurus sprite's actual WebGL draw and checks its world anchor against the native date frame; it also checks the real Sun hover placement. Numerical positions are unchanged.

## Verification

404 unit/numerical tests pass, including 30 recovery/network tests, display-preference privacy tests, scene policy/layout tests and a native-known-answer regression for 27 April 1987 at 02:00 in Melbourne. All 41 production browser workflows pass. Coverage includes keyboard summaries, collapsed/pinned panels, source cards, native dialogs/focus return, large text at 1440×900, 1280×720, 900×768 and 720×450 CSS reflow equivalents, exact eclipse overlap selection, translucent-Earth picking, context loss, data failure/retry, lookup outages and hidden-tab pausing. Axe WCAG-tagged scans cover welcome, body, house/construction, aspect, trail and dialog states. Automated scans establish their tested checks, not universal accessibility or manual screen-reader conformance. [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing).

Measured scene evidence is recorded in [M8 scene validation](M8-scene.md). On this host's documented software WebGL renderer, CPU layout/render-submission p95 was 2.9 ms in the default case, 9.7 ms during mixed-state warmup and 7.3 ms in the repeated warmed mix. Idle rendering stopped and repeated resource cycles plateaued. Software frame delivery did not establish the 60 fps target, and these are not physical integrated-GPU frame-time measurements.

Manual screen-reader work, actual Safari on macOS, physical reference-GPU measurements and moderated participant evaluation remain explicit release-validation evidence gaps. No substitute users, devices or results are invented. M9 provides the cross-browser/deployment checks and the remaining verification kit.
