# M3 — One coherent spatial sky

Implemented on `codex/m3-spatial-sky`, based on reviewed M2 development. Main remains at the original commit.

## Delivered

- Twelve selectable 30° tropical sign sectors, separate from real constellation regions. Bodies retain off-ecliptic latitude. A selected body highlights its sign and its longitude projection without moving the actual marker.
- Geometrically derived Ascendant/Descendant and Midheaven/IC, horizon, ecliptic, celestial equator, local meridian, prime vertical, zenith/nadir and celestial poles. Every feature has a definition, source and list selection. MC is explicitly distinct from zenith.
- Independent reference angles remain available when a chosen time-based house system fails. Exact poles and singular horizon/ecliptic orientations report undefined references. Literal rising/upper-transit references are distinguished from system-specific polar cusp conventions.
- Real Earth coastlines, observer marker/tangent orientation, three camera destinations, canvas picking, hover identity, selected-feature focus and keyboard list access. Ordinary Earth/observer inspection cannot edit coordinates. Only deliberate globe input proposes them.
- A restrained 2,865-star HYG v4.1 catalogue with explicit J2000/proper-motion policy, plus all 88 constellation regions (89 pieces including Serpens). Source and derived hashes, transformations, changes and CC BY-SA 4.0 notices are recorded in `sky-data-manifest.json`. The preparation script verifies upstream bytes before extraction.
- A live layer legend, below-horizon body encoding, bounded screen-size labels with overlap priorities, source-linked numerical context and expandable calculation provenance, including historical/future time-model limitations.

## Verification

- 105 unit/numerical tests: native Swiss angle agreement within 1e-6°, horizon/ecliptic intersections, upper meridian and eastern rising branch, date-frame transforms, singular/polar states, known Sirius direction, Arcturus motion, all constellation identities and source integrity, plus earlier milestones.
- Eleven production Chromium workflows cover input, recovery, camera invariance, keyboard sign/angle/constellation selection, explicit focus, layer restoration for selected reference points, and normal Earth/observer versus explicit globe input.
- Type/lint/build and all pinned asset checks pass. Independent UI review identified hidden zenith/pole selections; selecting them now enables their reference layer. Root review checked reference geometry, catalogue propagation, picking/occlusion, resource teardown and frame use.
- Desktop views inspected: default, all reference layers, Orion focus and observer ASC. The dock overlap found during inspection was fixed. Compressed initial application JavaScript including bundled catalogue/time data is about 574 kB; this excludes separate worker, WASM and ephemeris assets and is not a full network/performance measurement.

## Limits and next milestone

Catalogue stars are mean astrometric directions; apparent planetary corrections are not silently applied to them. Annual stellar parallax/aberration and variable brightness are omitted and documented. Boundary samples retain the source's declared transformation rather than an app-owned high-precision boundary transformation.

House displays, comparisons, construction guides, aspects, interpretation catalogue, timeline trails and comprehensive accessibility/performance validation remain assigned to M4–M9. This milestone establishes their shared spatial and selection foundation.
